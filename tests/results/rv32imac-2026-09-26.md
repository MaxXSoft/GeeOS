# RV32IMAC simulator validation (2026-09-26)

The matched comparison passed every original runtime, system, and smoke case.
On the final RTL, compiling the same fixed GeeOS source as RV32IMAC reduced
instruction-side AXI read requests by 67.32% in the system suite and
65.24% in smoke. Guest cycles fell 23.75% and 16.59%, respectively.
This supports improved instruction supply/cache locality in these workloads.
Hot standalone runtime tests benefited less: total cycles fell
2.07% versus the final RTL running RV32IMA.

## Matched Comparison

All three columns use the same GeeOS source, YuLang binary, simulator host
harness, and options. The new-RTL IMA column replays the exact old-RTL IMA ELF
files; their SHA-256 hashes were checked. The common software includes the ELF
entry and startup-stack fixes described below, so those fixes do not get
misattributed to compressed instructions.

| Smoke guest cycles | 36,364,562 | 35,337,205 | 29,474,385 |
| Smoke instruction-side reads | 400,413 | 393,472 | 136,789 |

These are single serialized passes, not repeated statistical benchmarks.
Runtime wall time sums case execution and excludes compilation. System wall time
covers boot and case execution, excluding image construction. Smoke reports the
whole invocation window. Small wall-time changes are within measurement noise:
the same IMA programs used -2.13% guest cycles on the new RTL
while host runtime wall time changed 0.41%.

Comparing the final RTL's two ISA builds, runtime/system/smoke wall time changed
-6.89%, -23.05%, and
-16.81%, respectively. Comparing old RTL/IMA with the final
RTL/IMAC gives -6.50%, -24.88%, and
-18.45%. Host elapsed time is not a hardware frequency or
IPC measurement.

Port 0 is the instruction-side AXI path. Its cache-refill traffic can include
page-table reads, speculative requests, and refills canceled by redirects; it is
not a retired-instruction count or a direct instruction-cache-miss counter.
System/smoke counters also include host-paced UART waiting. Code size, code
layout, branch prediction, ELF loading, and interrupt overhead can all affect
total cycles. The reduction in instruction-side traffic is the direct evidence
relevant to fetching. Dhrystone/CoreMark IPC is recorded separately in
verilator-axi-testbench.

## Correctness And Fixes

Final Fuxi validation passed 20/20 runtime case/optimization combinations, all
9 system cases, and interactive smoke. QEMU also passed 20/20 runtime, 9/9 system,
and smoke. Host GeeFS, adapted HashMap synchronization, mkfs incremental rebuild,
Python compilation, YAML parsing, all 13 workflow shell scripts, and
`git diff --check` passed.

Compressed compilation exposed an existing ELF-loader assumption: the shell's
entry became `0x12d66`, and `entry % 4 == 0` rejected it, causing
`KERNEL PANIC: initProcess` during QEMU boot. The loader now accepts halfword
alignment. The new assembly fixture forces entry `4n+2`, executes full-width
instructions and ECALL there, and rejects an otherwise identical ELF whose
entry is odd.

Trap-vector entries remain four-byte aligned: explicit alignment was added to
the bootloader handler, machine timer handler, and runtime test trap handler.
ECALL still advances the saved PC by four bytes.

A separate existing ABI bug used four-byte startup-stack alignment. The original
kernel's `_stack_top=0x800cdbcc` and bootloader's `_stack=0x2064` violated the
emitted ABI's 16-byte requirement. The linker/assembly now align them to 16;
`host/check_stack_alignment.py` rejects the original ELF and accepts the fixed
kernel and bootloader. CI runs this check after building. Both matched ISA builds
include these fixes.

## Reproduction And Artifacts

Build each ISA in a separate directory. Use `RISCV_ARCH=rv32ima` or the default
`rv32imac` for make, and the corresponding `--march` for runtime/system tests.
Enable `--simulator-stats` consistently. See the [test instructions](../README.md)
for toolchain and suite commands.

Local raw logs, exact commands, executable hashes and full per-run JSON are in:

- `build/imac-comparison/baseline-final-stats/`: common-source IMA on old RTL.
- `build/imac-comparison/post-ima-final-stats/`: identical IMA ELFs on final RTL.
- `build/imac-comparison/post-imac-final-stats/`: IMAC on final RTL, matched cases.
- `build/imac-comparison/post-imac-full-system/`: all nine IMAC system cases.
- `build/imac-comparison/qemu-imac/`: QEMU validation.
- `build/imac-comparison/matched-ima/` and `post-imac/`: kernel build products.

The local orchestration/replay scripts are also under `build/imac-comparison/`.
CI now pins the final testbench revision and preserves simulator statistics in
the existing log artifacts. The GitHub-hosted workflow was not run.
